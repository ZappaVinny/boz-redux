# CLAUDE.md

BOZ Redux client: runs the Android release of *Call of Duty: Black Ops Zombies* (Ideaworks, Marmalade SDK 10) on PC from the user's APK. The game logic is 32-bit ARM code inside `boz.s3e`; this repo's runtime runs it on x86 Linux and Windows. Focus: a fast, correct client (later: the mod runtime, LAN co-op without online services, the 64-bit rebuild).

Sibling repos (local layout `~/Work/boz/`): `../boz-redux-sdk` (reverse engineering, Ghidra, bozkit, modding docs) and `gamedef/` (submodule, boz-redux-gamedef: symbols, reflection, events, console; generated by the SDK, pinned here for the mod runtime).

## How the runtime works

The runtime is a fork of [cod-boz-port](https://github.com/Producdevity/cod-boz-port) (MIT, fork point 3b444d6; notice in `LICENSE-cod-boz-port`). Upstream runs the ARM code natively on ARM handhelds and implements the Marmalade (s3e) API in C. The fork adds:

- `src/arm_emu.c`: Unicorn-based ARM CPU. The loader is built as 32-bit x86 so guest and host share addresses. Host memory is identity-mapped into the emulator on first touch (whole `/proc/self/maps` regions). Any guest jump into host code lands on a shadow page of `svc` instructions; the trap calls that x86 function with r0-r3 plus stack words and returns r0:r1. No thunk table.
- `s3e_guest_call()` (in `s3e_host.c`): every place the C code calls back into game code goes through it.
- Desktop input in `s3e_input.c`: mouse pointer in menus; game mode (mouse captured) follows the game, on while a match's player update runs (paused = menus). In Zombies, `src/native_input.c` sends input straight to the game through gamedef symbols: mouse counts added to `CPlayerController` yaw/pitch at the start of `FixedStep`, movement as `CInputManager::SendAnalogStick` from the move pad's update, buttons as `CInputManager::OnInputAction`. Dead Ops (and `BOZ_TOUCHPAD_CONTROLS=1`, or missing symbols) keeps the old path: WASD on touchpad 0 stick, mouse on the touchpad 1 stick, Xperia Play keys. Pause is still the Xperia pause key.
- Linux with NVIDIA: the 32-bit driver has no working EGL for windows (glvnd falls back to Mesa: software rendering on Wayland, a crash on XWayland), so the launcher and `run-desktop.sh` use SDL's X11 driver there (unless a 32-bit `libnvidia-egl-wayland` exists) and `s3e_egl.c` creates the OpenGL ES context through GLX itself (`create_glx_es_context`, like the Windows WGL path; SDL never uses GLX for ES 1).
- Window scaling in `s3e_gl.c`: game renders to a 1280x720 FBO, blitted to the window each swap. Super+W/close maps to `s3eDeviceRequestQuit`.

PC-specific changes to the game itself live in `src/game_patches/` (declared in `include/game_patches.h`):
- `crash_recovery.c`: repairs known crashes at fixed image offsets in the emulator's fault hook. Recoveries log `[arm] recovered ... fault` once per site; unrecovered faults print registers, `image+0x...` offsets and the stack.
- `frame_interpolation.c`: renders between fixed game steps, found through gamedef names; a missing name only warns.
- `player_name.c`: points the game's `Player-%d` name at `client.ini [player] name`.
- `hud_sticks.c`: blanks the virtual-stick art in the `HUD_ALL` texture of any `ingame.group.bin` served (pack, loose file or mod copy); off with `BOZ_TOUCHPAD_CONTROLS=1`.

## Layout

- `src/`, `include/`, `tests/`: the desktop runtime. Build with CMake presets: `cmake --preset linux-x86`, `cmake --build --preset linux-x86` (`linux-x86-tests` builds tests too), `ctest --preset linux-x86`. Outputs go to `build/linux-x86/bin/` (loader, extractor, `libSDL2`; loader RUNPATH is `$ORIGIN`). Then `scripts/setup-game.sh`, `scripts/run-desktop.sh`.
- Windows: `cmake --preset windows-x86 && cmake --build --preset windows-x86 && scripts/package-windows.sh` (MinGW-w64 cross build). Windows renders through ANGLE (Direct3D 11; `libEGL.dll`, `libGLESv2.dll`, `d3dcompiler_47.dll` from Electron's win32-ia32 release, `scripts/fetch-angle-windows.sh`) on the same SDL + EGL path as Linux. ANGLE has no ETC1, so `s3e_gl.c` reports the extension to the game and uploads ETC1 as ETC2. `client.ini [display] renderer` = d3d12/vulkan/software (`BOZ_RENDERER=mesa` + `GALLIUM_DRIVER`) uses the bundled Mesa in `mesa\` instead, through WGL (`WGL_EXT_create_context_es_profile`; `src/platform/gl_probe_win32.c` probes drivers). Mesa's Direct3D 12 driver exits with 0x80070057 on some AMD GPUs; the launcher then switches to software. `platform_win32.c` logs first-chance crashes (Unicorn's code-buffer commit faults are expected). Linux tarball: `scripts/package-linux.sh`. CI: `.github/workflows/build.yml`; tags `v*` publish a release. Its `windows-test` job runs the Windows build on Windows (`scripts/test-windows.sh`: every unit test exe, then the extractor and launcher start); tests must stay portable (`tests/test_support.h` for temp dirs, no `/tmp` or shell commands).
- `third_party/patches/unicorn-*.patch`: applied to the Unicorn submodule at configure time, in name order (TLB/dirty-tracking speedups, stores to code-free executable pages on the fast path, precise store faults without the per-access exit check, flush counter, Windows code-buffer commit fix). CMake reverse-checks each patch to see whether it is applied, so a patch's context must not overlap another patch's changes: extend the existing patch instead. Linux builds Unicorn and the loader without PIC (`-no-pie`), which is 15-20% faster on 32-bit x86; tests that link Unicorn need `-no-pie` too.
- Launcher: `boz-redux` (`src/launcher/`, C++17, Dear ImGui submodule on SDL's 2D renderer). It installs the APK (runs `codboz_apk_extract`), downloads packs with `curl` or imports them (SHA-256 checked), edits `client.ini` in place (`ini_file.cpp`), and starts `codboz_s3e_loader` with `HOME=<root>/saves`, logging to `boz-log.txt`. Its key list is `CLIENT_BINDINGS` from `client_config.c`, the same table the loader uses. Dev: `scripts/run-launcher.sh`.
- `third_party/SDL2_mixer`: submodule (release-2.8.2), built shared with only minimp3 and WAVE decoders; bundled next to the loader on both platforms.
- `third_party/unicorn`, `third_party/SDL2`: submodules, built 32-bit as CMake subprojects via `cmake/i686-linux.cmake` (the `gcc-m32` wrapper is required; Unicorn's CMake ignores `-m32` flags).
- `gamedef/`: submodule (boz-redux-gamedef), the game definition the mod runtime will read. Update it by moving the submodule pin to a commit the SDK published; check `schema` in `gamedef/gamedef.toml`.
- `branding/`: the approved BOZ Redux brand for the client (icon sizes, `boz-redux.ico`, logo, mark, Barlow fonts with their OFL). CMake embeds the logo, icon and fonts into the programs (`boz_branding`, `include/branding.h`, colours there too) and gives every Windows `.exe` the icon and version resources (`packaging/windows/app.rc.in`); `src/branding/brand_imgui.cpp` is the ImGui colour scheme the launcher and the in-game overlay share. Linux packages get `boz-redux.png` and `add-to-menu.sh`; the window class is `boz-redux`. The originals are in `original/BOZ_Redux_Approved_Brand` (the logos there have a faint grey haze, removed in the copies).
- `original/` (gitignored): `com.activision.boz.apk` (1.0.11) and `obb/` with the CDN packs plus `.dz.dat` markers.
- `assets/` (gitignored): extracted game data and pack links, made by `setup-game.sh`. The repo root is the game root (`--root`); the port looks up files in `<root>/assets/`.
- `mods/` (gitignored): installed mods, one folder each (`mod.toml`, `assets/`, later `scripts/`). `src/mods.c` scans them; the launcher's Mods tab writes `client.ini [mods] order/disabled`; `s3eFileOpen`/`s3eFileCheckExists` check enabled mods' `assets/` first (whole path, then file name, no case; later mods win). `[debug] log_files` (`BOZ_TRACE_FILES`) logs every open. A manifest's `maps = [...]` lists the levels a mod adds; with any, PLAY opens a chooser (`play_chooser`): each map solo or as a co-op room, or the main menu. It writes the one-shot `autostart_level` (and `autostart_mode = coop`) into that mod's `saves/mods/<id>.cfg` (`mods_set_setting`); the map mod's `boz.world` (`boz.levels.autostart_from_settings`) starts the level, or opens the game's Wi-Fi lobby with the map as its level (rooms are matched by map name).
- Code mods: `src/lua_runtime.c` (Lua 5.4 submodule `third_party/lua`, one state on the game thread; runs each enabled mod's `scripts/main.lua` in its own env at the first swap; `settings` and `assets` modules in `lua_settings.c`, `lua_assets.c`, shared internals in `src/lua_runtime_internal.h`), `src/lua_hooks.c` (`hook` module on `arm_emu_hook_add`: per-address Unicorn code hooks, return trap for after handlers), `src/game_image.c` (image base, gamedef name to address), `src/gamedef.c` (reads `<root>/gamedef` or `<exe>/gamedef`; packages bundle it), `src/overlay.cpp` (ImGui core + own GLES2 renderer on `lookup_gl`, drawn in `host_eglSwapBuffers` after `scale_present`; input from `input_pump`'s `SDL_PollEvent` loop; `overlay.capture` takes all input from the game). API reference: `../boz-redux-sdk/docs/lua-api.md`. The client has no game-specific Lua: the standard lib (`boz.*`) lives in `../boz-redux-sdk/lib/boz` and mods carry a copy (`scripts/boz`); the SDK's Developer mod is linked into `mods/`. Lua hooks: `assets.patch` (s3e_file.c serves patched files from memory), `shared` (one table all mods see). Mods start right before the game's entry point (main.c) so hooks and patches see everything.
- `saves/` (gitignored): game saves and `device-id.bin`. `run-desktop.sh` sets `HOME` to it (override with `BOZ_SAVES`) and keeps `XDG_CACHE_HOME` on the real cache.

Never commit game files (`*.apk`, `*.dz`, extracted assets).

## Game facts

- Target version 1.0.11 (versionCode 1045111). Packs come from `http://cdn-boz-android.callofduty.com/PROD/CODBOZ/1_0_9/`. The runtime needs `blackops_etc.dz` and `blackops_gles1.dz`; upstream setup expects SHA-256 `670cefce...` and `60846cf7...`.
- The local APK is genuine game payload but a re-signed repack (adds `com.savegame.SavesRestoring` and `assets/su.save`, a premade save). The extractor skips `su.save`.
- Image loads at `0x4a000000`. Game `memcpy` is at image offset `0x366000`.

## Debugging

- `BOZ_TRACE_STATUS=1`: status line every 2 s (host call rate, last host function, main ARM pc/lr).
- Performance: `[performance] stats` (`BOZ_PERF_STATS`) logs frame times and per-frame counters; `scripts/bench.sh kino|apothicon` measures a build offscreen in a throwaway root (alternate builds when comparing, single runs vary ~5%); `BOZ_PROFILE=all` samples host and guest PCs (Linux). The hot path is the host-call trap in `arm_emu.c` (thousands per frame): keep it free of system calls and symbol lookups (`host_code_address` caches pages).
- `BOZ_TRACE_CALLS=N`: log the first N host calls with arguments.
- Emulator faults print `[arm] ... pc= lr=` with all registers.
- Settings: `<root>/client.ini` (`src/client_config.c`) is translated into `BOZ_*` variables at startup (including `[player] name`, `[network] server` and `voice_chat`); a variable already set wins. `docs/runtime.md` lists every variable.
- Other env: `BOZ_DISPLAY=WxH`, `BOZ_STRETCH=1`, `BOZ_NO_SCALE=1`, `BOZ_LOOK_SENS` (default 3.0, 0.022 degrees per count), `BOZ_AIM_SENS`, `BOZ_INVERT_Y=1`, `BOZ_TOUCHPAD_CONTROLS=1` (old touchpad input everywhere); Dead Ops touch stick: `BOZ_MOUSE_SENS` (default 12000), `BOZ_LOOK_RADIUS`, `BOZ_LOOK_MODE=swipe`.
- Reverse engineering (Ghidra, symbol tools) lives in `../boz-redux-sdk`; see its `docs/reverse-engineering.md`.

## Building

- Building needs 32-bit libs: `lib32-glibc`, `lib32-mesa`, `lib32-libglvnd`, `lib32-libxkbcommon`, `lib32-libdecor`. SDL2 is built from the submodule, not installed.
